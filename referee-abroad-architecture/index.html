Platform architecture · proposal

From WordPress today to a platform you fully own

A three step rollout that grows the platform without disrupting what already works. Each step ships on its own and delivers value before the next one starts.

How to read the diagrams New, built for Referee Abroad Existing or external system Data, the single source of truth One time or manual
Today

Everything runs on WordPress

Referees browse, apply and pay through a WooCommerce webshop. WordPress is both the website and the database, and everything around it is run by hand.

One platform: WordPress + WooCommerce holds all the data.
Everything else runs on manual spreadsheets and email.
No direct communication channel to referees.
Step 1
Phase 1

Build alongside, replace nothing

Add an admin dashboard for the team and a mobile webapp for referees. All data keeps landing in WordPress; payments keep running through the proven WooCommerce checkout.

Nothing on the current site changes.
WordPress stays the single source of truth.
Referees get in app messages + push notifications.
New referees can apply & pay in app, via the existing checkout.

The dashboard and webapp read and write through WordPress' API, so a signup made in the app becomes a normal WooCommerce order. WordPress stays in charge. The apps only add their own layer (chat, notifications, read status).

Step 2
Phase 2

The Tournament Command Centre

The dashboard grows into one command centre for every tournament and all referee communication. A new website replaces WordPress, and the data moves into a database Referee Abroad fully owns.

The dashboard becomes the Tournament Command Centre.
A new website replaces the WordPress site.
All data is migrated into an own database, once.
Full ownership, no WordPress dependency left.

Phase 2 is bigger than a data move: the Command Centre, the own database and the new website together replace the entire WordPress layer. That is why it comes only once Phase 1 is live and proven.
